# AGENTS.md

## Project

Read README.md, docs/features.md and docs/architecture.md before changing behavior. gendock curates and packages local text/image/audio/video solutions for nontechnical users and agents; normal callers choose tasks/models, not inference engines. This is a Rust CLI foundation for unified AIGC, initially targeting macOS Apple Silicon. Do not confuse planned capabilities with implemented features.

## Rules

- docs/features.md is the canonical feature-status table. In every feature/fix PR that changes availability or scope, update status, readiness percentage, evidence, limitations and next steps in the same PR. Percentages are engineering estimates, not line coverage. 60% means basically usable; 100% requires complete acceptance within the row's stated scope. Command stubs remain 0%; queue primitives do not count as a working shared scheduler. Lower scores when regressions justify it.
- Resident service, durable scheduling and completion notifications are required for 20+ colleagues sharing one device remotely. Keep schema small and reuse jobs/state where appropriate; do not downgrade these features to optional merely to avoid table growth. Preserve local synchronous CLI mode. Start GPU concurrency at one, with authenticated task ownership and uploaded/authorized inputs; never expose arbitrary host paths remotely.
- Service queued work uses existing job IDs and the same image core. Keep admission limits/claiming atomic, instance ownership fenced and heartbeat/cancellation checks active during full file verification and inference. Recover only under the shared OS image lock; live/reused worker PIDs and fresh live handoff leases block overlapping work. Normal shutdown preserves queued tasks and interrupts active work; never automatically replay interrupted work.
- Remote replies omit server paths/private logs; tokens remain owner-only. Client exports use client configuration. Do not persist a foreign client path as a server-local output. SSE reconnect sends the current snapshot, not historical replay; use persisted polling fallback. Server residency does not imply model residency.
- Use XDG paths on macOS. Keep configuration, durable data, state and cache separate.
- Image defaults come from XDG config.toml (`defaults.image_generate`, `defaults.image_edit`), with per-invocation --model override. Initialize only when absent, preserve user edits, reject invalid configuration, and never auto-download models during generation/editing. Missing local defaults return model_not_installed plus an actionable download command.
- Editing validates PNG/JPEG/WebP inputs and archives exact bytes before execution. Record source/snapshot paths, hash and dimensions; never pass a mutable original to the worker or overwrite it.
- Normal generation callers choose a model/task, never a backend or Python. The first synchronous image recipe uses a registered, fingerprinted private component; do not discover workers on PATH. Linked private environments are a development bridge, not a completed self-contained installer. Read docs/image-generation.md before editing execution.
- Never depend on system/user Python, pip, Conda or mutable global environments. Private backend runtimes are versioned and managed by gendock.
- Model search reads the SQLite `model_catalog` table. Bundled JSON is a versioned release seed, not a second search source. Increment `BUILTIN_CATALOG_REVISION` for shipped metadata changes. Reconcile transactionally, preserve user IDs/definitions and all local files, retain removed built-ins as deprecated/nonrecommended, and never downgrade a newer catalog revision.
- Model downloads use immutable revisions and expected file identities from the local catalog. File URLs can be HF, public R2 or another direct HTTPS origin; do not require arbitrary CDNs to emulate HF. Distinguish `--endpoint` (HF or mirror) from `--proxy` (network proxy). Never send official HF_TOKEN to a mirror. Routine tests use local HTTP fixtures; the opt-in live test downloads only a README.
- External models are references. Never delete or modify referenced weights, even when removing a registration.
- Do not run model downloads or multi-GB installations as routine tests.
- Keep storage and scheduling independent of CLI presentation and future GUI code.
- Persist explicit model revision, backend and effective parameters when generation is implemented.
- Image output without `--out` exports to the invocation directory using local-time `image_MMDD_HHMM.png`, with `_2`, `_3`, etc. on collision. Explicit output paths never overwrite. Always return/persist the actual export path; keep managed assets for history/recovery.
- Synchronous image execution must hold the OS lock, record CLI/worker identity, reap its owned child on cancellation/errors, preserve logs and verify output before success. Recover abandoned sync jobs conservatively; never kill an unverified/reused PID or consume queued jobs through the sync path. Export failures preserve successful assets and never overwrite existing files.
- Before 1.0, keep all table/index definitions in the single migrations/001_initial.sql snapshot; do not append upgrade scripts. Initialize empty DBs transactionally, reject incompatible development schemas without resetting/deleting data, and keep the schema marker aligned. After 1.0, use transactional versioned migrations for released user databases. Never hold a write transaction across inference.
- Do not copy Phosphene source or assets into this repository without preserving applicable attribution/licenses. It is a reference project, not a dependency.
- Error responses follow `docs/json-contract.md`: versioned envelope; stable code, concise message, retryable flag, structured details and actionable next_steps. Never embed rendered clap usage or multiline terminal errors in message. Preserve legitimate newlines in user content; JSON escaping is required.
- Operation results/errors and version information return JSON on stdout by default. Exceptions: bare invocation/groups/help show human-readable help, and successful foreground `server start` streams timestamped, leveled console logs (TTY colors, NO_COLOR honored), without final success JSON. Startup failures remain JSON. `--daemon` and `--register` are JSON control operations; keep console and structured event log files separate. Do not add `--json`. Preserve exit codes and document schema changes.
- Record every handled HTTP request, including failed authentication/capacity rejection, with request ID, actual path (including unmatched routes, bounded to 2048 characters), peer, status and duration; 4xx WARN, 5xx ERROR. Never log authorization values, query strings or bodies. Escape path text to preserve one-line logs. Preserve X-Request-ID on JSON, file and SSE responses. Advertise localhost/LAN addresses with accurate listener scope; displaying an IP must not silently change the default loopback bind.
- macOS login registration uses launchd label `gendockd`: keep the canonical plist in XDG config and only the OS-required symlink in ~/Library/LaunchAgents. Carry explicit HOME/XDG roots, never copy tokens into the plist. Serialize registration changes, preserve unrelated files and roll back new files on failure. `server unregister` removes only owned registrations. Login startup differs from a pre-login system daemon.
- Planned commands may be exposed as explicit JSON `not_implemented` failures with exit 3 and no storage/download side effects. This is the user's chosen contract; never return fake success.
- Never claim generation works until a real backend has been exercised.
- Core behavior requires meaningful unit/integration tests. New user flows need chained CLI E2E acceptance, not just isolated unit tests. Keep `scripts/e2e.sh` deterministic with tiny workers and temporary XDG roots. `scripts/e2e-real.sh` explicitly runs the release-build real-model pipeline with read-only existing models/runtime and isolated host/client state; never treat simulated inference as actual model validation. `cargo test` is the standard pass/fail entry point; line coverage needs a separate cargo-llvm-cov run. Never imply tests passing means full coverage.
- No credentials, model files, user database, logs or generated media in Git.

## Verification

Run `cargo fmt --all --check`, `cargo clippy --all-targets --all-features -- -D warnings`, and `cargo test --locked`. Add meaningful tests for persistence, migration, ownership and concurrency changes. Use temporary XDG roots; do not modify the developer's real data.

## Maintenance knowledge

Read `.agents/skills/gendock-maintenance/SKILL.md` for work on storage, queues, runtimes or release checks. Update its references when discovering a reproducible pitfall or changing an architectural contract. Record the cause and verification, not transient session logs. Update README/roadmap when capabilities change.
