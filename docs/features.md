# 功能进度与完成度

这是 gendock 的功能状态总表。新增功能、修复影响可用性的问题或改变支持范围时，必须在同一个 PR 中更新本表。

## 产品定位

gendock 为用户筛选、验证并封装文字、图片、音频和视频领域实用的本地 AI 方案，通过统一 CLI 和后续服务接口交付能力。普通用户只需要描述任务、选择模型；模型文件、运行组件、硬件适配和推理参数由工具管理。用户也可以直接与 Agent 对话，让 Agent 操作 CLI。

本机独立创作与多人共享设备都是产品范围：公司里 20+ 人可以从其他电脑向一台 Mac 提交任务，由常驻服务排队执行并通知结果。队列、服务和通知是必做功能，同时保持 SQLite 设计精简。

**评估基线：0.1.0 开发版；已真实验证的生成环境为 M4 Pro / 48 GiB、FLUX.2 Klein 4B q4。文字、音频、视频方案尚未完成端到端接入。**

## 完成度标准

百分比是按每行声明范围做的保守工程评估，不是代码量、测试覆盖率或整个产品的平均进度。

| 完成度 | 含义 |
| --- | --- |
| 0% | 未实现；即使已有命令入口，也只返回 `not_implemented` |
| 20% | 有底层基础，尚不能完成用户流程 |
| 40% | 部分关键环节已实现，仍有阻断项 |
| 60% | 基本可用，已有端到端验证，但支持环境/模型有限或仍需人工准备 |
| 80% | 声明范围内的常用流程可用，仍需补兼容性、诊断或使用体验 |
| 100% | 本行明确范围内完全可用，验收与文档齐备，无已知阻断项；不代表支持所有未来模型或保证永无缺陷 |

状态与百分比一起阅读。基础模块完成，不代表缺少安装器的新机器已经能直接创作。发现回归时，应降低完成度并写明阻断项。

## 技术方案选择记录

普通用户面向任务和模型，下面的技术选择由项目维护者管理，不应成为用户使用命令的前置知识。

| 领域 | 当前选择或候选 | 验证程度 |
| --- | --- | --- |
| 图片 | FLUX.2 Klein 4B q4；私有 mflux + MLX 组件，通过 Metal 使用苹果 GPU | 本机生图、指令编辑均已验证；自动组件安装未完成 |
| 文字 | 面向 Apple Silicon 的本地文字模型及对应组件；具体默认方案待评估 | 未完成选型/接入 |
| 音频 | 转写、语音、音效、音乐分别选择合适模型和流程，不假设一个模型覆盖全部 | 未完成选型/接入 |
| 视频 | 候选 LTX 系列及适配运行组件 | 尚未接入 gendock，不能宣称可用 |

选择标准：实际质量和中文效果、内存门槛、速度、稳定性、许可证、离线能力及上游维护状况。“主流”需要持续验证，不是下载量排名或一个后缀就能决定。

## 下一阶段验收重点

1. 共享服务扩大验收：跨物理设备、真实多人长时队列、断网恢复、资源压力；补充提交幂等、凭据轮换、素材配额和清理。
2. 完成通知深化：目前 SSE 当前快照与查询回退可用；按需求补可靠 webhook 投递及事件历史，不预建通知表。
3. 私有运行组件自动安装：新 Mac 无需用户处理 Python/底层工具即可准备组件；执行时缺模型仍按规则报错，不擅自下载。
4. 逐步扩展文字、音频、视频：每增加一项，先明确模型与运行组件，再用真实任务验收，不以命令占位或 mock 测试宣称生成成功。

## 维护与证据

- 修改实现、支持范围或修复可用性回归时，同步更新对应行的状态、百分比、限制及下一步。
- 只有完整走通声明范围并有验证证据，才能标 100%；命令占位永远是 0%。纯存储基础不能标成共享服务已可用。
- 当前实际能力由 `src/app.rs` 分发及对应实现决定；命令语法见 [commands.md](commands.md)，计划顺序见 [roadmap.md](roadmap.md)。
- 自动化验证主要在 `tests/` 与模块单元测试；执行命令及脚本见 [testing.md](testing.md)，服务边界见 [server.md](server.md)；图片实测另见 [image-generation.md](image-generation.md) 和 [mflux-cli-validation.md](mflux-cli-validation.md)。
- 测试通过数量与本表完成度是两套指标；未运行覆盖率工具时，不报告行覆盖率。
